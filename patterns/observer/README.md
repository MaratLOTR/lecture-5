# Observer — Наблюдатель

## Пример из лекции

TemperatureSensor хранит подписчиков с методом update(value).
Display печатает температуру, Log хранит её в values. Подписка не отправляет
начальное значение. Повторная подписка не дублируется, повторная отписка допустима.
set_value() сначала меняет value, затем синхронно уведомляет подписчиков.
Одинаковое значение не создаёт событие. В демонстрации журнал получает [21, 22].

Роли: TemperatureSensor — Subject, update(value) — контракт Observer,
Display и Log — ConcreteObserver. Здесь используется Push: издатель передаёт значение.
Pull-вариант передал бы источник, из которого подписчик прочитал бы данные.
Подписчик реализует метод по соглашению, отдельный Protocol не требуется.

Обход tuple(_observers) фиксирует состав текущей рассылки. Новая подписка или отписка
внутри update() влияет на следующую рассылку. Исключение прерывает текущую рассылку,
но значение датчика уже обновлено. Ссылки удерживаются до отписки. Порядок соответствует
порядку подписки. Многопоточность, повторные попытки и вложенные рассылки не регулируются.
Классы примеров не переопределяют __eq__: проверка повторной подписки сравнивает объекты.

## Запуск из этой папки

```bash
python3 __main__.py
python3 -m pytest tests/test_example.py
python3 -m pytest tests/test_task.py
```

Нужен Python 3.10+ и pytest из requirements.txt. Тесты запускаются через pytest.
Классы unittest.TestCase совместимы с pytest, как в проекте лекции 3.
Готовый пример проходит сразу. Задания намеренно не реализованы: сначала прочитайте
TASK.md, затем добейтесь прохождения тестов без пропусков.
Дополнительная проверка: `python3 -m pytest tests/test_extra.py`.
